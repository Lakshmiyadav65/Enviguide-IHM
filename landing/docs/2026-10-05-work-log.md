## 1. Contact form emails through Resend

### Before

The demo form, now [src/pages/BookDemoPage.jsx](../src/pages/BookDemoPage.jsx), had no submit handler. Clicking "Request Demo" reloaded the page and the request was lost.

### What was built

[api/contact.js](../api/contact.js) is a new Vercel serverless function, set up like the existing [api/chat.js](../api/chat.js). It runs on each submission:

1. The browser sends the form as JSON to `POST /api/contact`.
2. The function checks every field:
   - Required: first name, last name, email, phone, company, fleet size and role.
   - Optional: flag state and notes.
   - It also checks the email format and a maximum length per field, and collapses extra whitespace.
3. **Spam trap:** the form has a hidden `website` field that people never see. If it's filled in, the request is from a bot, so the function reports success and sends nothing.
4. The function calls Resend's API (`https://api.resend.com/emails`) and sends one email:
   - **To:** oceanledgerofficial@gmail.com
   - **Reply-To:** the customer's email, so replying in Gmail goes straight to them
   - **Subject:** `Demo request: <First> <Last> (<Company>)`
   - **Body:** a simple table of the fields, as both HTML (escaped) and plain text
5. The page shows "Sending…", then the existing "Demo Request Received!" message. If sending fails, it shows an error with a WhatsApp link.

Status codes the function returns:

| Code | When |
|---|---|
| 200 `{ok:true}` | Sent (or caught by the spam trap) |
| 400 | Missing or invalid field |
| 405 | Request that isn't a POST |
| 500 | `RESEND_API_KEY` isn't set |
| 502 | Resend rejected the request or couldn't be reached (the reason is in the function logs) |

The form sends the visible option text (for example "11-50 vessels") rather than the internal value, so the email reads naturally.

### Settings

| Variable | Required | Default | Purpose |
|---|---|---|---|
| `RESEND_API_KEY` | Yes | none | Resend API key with "Sending access". Set on `ihmm-landing-page` for Production, Preview and Development, marked sensitive |
| `CONTACT_TO_EMAIL` | No | `oceanledgerofficial@gmail.com` | Overrides the inbox. Separate several addresses with commas |
| `CONTACT_FROM_EMAIL` | No | `OceanLedger IHMM <onboarding@resend.dev>` | Overrides the sender. Its domain must be verified in Resend |

> **Sender:** `maricomx.com` isn't verified in Resend yet, so emails come from Resend's test sender, `onboarding@resend.dev`. That sender can only deliver to the email address the Resend account belongs to, which is oceanledgerofficial@gmail.com. Once the domain is verified, set `CONTACT_FROM_EMAIL` to `OceanLedger IHMM <noreply@maricomx.com>` (see section 7).

```bash

# List, add or remove landing page settings

# Run the site and the /api functions locally (npm run dev serves the site only, without /api)

```

### Things to watch for

- **Git Bash and `vercel api`:** Git Bash on Windows rewrites arguments that start with `/` into Windows paths. Prefix calls with `MSYS_NO_PATHCONV=1`, for example `MSYS_NO_PATHCONV=1 vercel api /v9/projects/ihmm-landing-page/domains`.
- **`vercel domains add --force` across accounts:** it can remove a domain from the old project and then fail to add it to the new one with `alias_conflict` when another Vercel account holds the domain. Adding it through the project-domains API (`POST /v10/projects/<project>/domains`) works, and Vercel then asks for TXT verification.
- **Login design:** `maricomx.com/login` shows whatever `ihm-enviguide.vercel.app` serves. Change the login in the platform repo, not in the `Enviguide-IHM/` copy inside the landing folder.
- **`.env.local`:** it holds `RESEND_API_KEY` and the Vercel token. Git ignores it and Vercel never uploads it. Don't commit it.
